# Agent Note: Migrating Impart to ChatLuna V2

Status: implemented

## Problem

Upstream impart-pro 2.0.0 at `9898c928054af924f1e9c5a46eff145e3060eee5` depends on legacy Koishi plugin wiring, Puppeteer, currency and font services. The requested V2 migration removes maintenance, duels, rerolls, individual locks, injection, currency and custom fonts, retaining group controls and adding reverse mining.

## Decision

- Register commands on the current Cordis 4 context using the host Koishi bridge, Satori messages, database and permissions. Do not create another application or AI tools.
- `src/game.ts` uses real transactions and an instance-local serial queue. Player length and cooldown remain shared across groups on the same platform. Separate player, group and historical-membership tables use structured JSON identity keys instead of mixing users with synthetic channel rows.
- Store length as integer hundredths of a centimeter with no gameplay floor. Reject unsafe integer overflow and roll back. Preserve target-first, actor-second initialization, with no growth during initialization; initialization and both successful and failed valid actions consume cooldowns.
- Mining is a new design, not an upstream feature or an externally verified universal meme rule. Success subtracts length and failure adds it; training is the reverse. Mining looks up the existing success bands using negated length. Both share cooldowns; mining rankings sort signed lengths ascending.
- Upstream only registers toggle-based lock aliases, not the requested start/end names. New group commands set explicit idempotent states, default to open, and pause profile/ranking commands without deleting data.
- Administrative commands explicitly recheck host level 3 permissions. Cross-user actions validate current-platform group membership. Removed personal locks are not reintroduced through the UI.
- `src/render.ts` uses Takumi 1.8.7 node trees, cached offline Noto Sans SC fonts and at most two concurrent renders. Names become text nodes, no avatars are downloaded, unload cancels rendering and failures return explicitly labelled text rankings.
- `client/` uses ui-kit, locale and typed state/action APIs. The server validates both action schema and permission; ranking DTOs omit cooldown timestamps and enforce result limits. Pages retain the host scrolling and overlay behavior.
- Only the standalone source is edited and copied to the workspace through an allowlist. Acceptance runs use an isolated host configuration and SQLite database. Retain the upstream MIT notice.

## Alternatives considered

- Per-group lengths would change the original cross-group game, so only controls and memberships are group-scoped.
- Toggle-based controls contradict start/end semantics and are unsafe to retry.
- Browser screenshots or remote fonts violate the requested rendering and font boundaries.
- Automatic legacy table conversion lacks platform mapping and explicit data-migration authorization.

## Consequences

New tables do not automatically import legacy Koishi data. Targets must belong to the current group. Mining failure rebounds toward positive lengths. Rankings describe historical participation, not current membership. Host permissions determine platform role mapping; the plugin never grants authority. Host ui-kit themes, thin native scrollbars and overlays take precedence over global custom-scrollbar preferences.
