# Agent Note: Impart 的 ChatLuna V2 迁移

Status: implemented

## Problem

上游 `koishi-shangxue-apps/plugins/impart-pro` 2.0.0（检索提交 `9898c928054af924f1e9c5a46eff145e3060eee5`）依赖旧 Koishi 插件装配、Puppeteer、货币与字体服务。用户要求迁移到 V2，移除保养、决斗、重开、个人锁定、注入、货币和自定义字体，保留群开关，新增反向挖矿。

## Decision

- 通过 Cordis 4 当前上下文注册命令，使用宿主 Koishi 桥、Satori 消息、数据库和统一权限。不存在第二套应用或 AI 工具。
- `src/game.ts` 使用真实事务和实例内串行队列，跨群共享玩家长度与冷却。玩家按平台及用户隔离；群开关和历史参与关系使用独立表，主键是结构化身份的 JSON 字符串，避免原版用户 ID 与频道伪用户冲突。
- 长度保存为整数百分之一厘米，修复操作显示与实际精度不一致；无业务下限，超出 JavaScript 安全整数范围时拒绝并回滚。初始化顺序保留 target → actor，首次仅初始化且消耗冷却；有效操作无论成败均消耗双方冷却。
- 挖矿是新增设计，不是上游已有功能或已核实的统一梗规则。成功缩短、失败增长，打胶恰好相反；挖矿用负长度匹配原成功率表。共享冷却阻止交替绕过，挖矿榜按有符号长度升序。
- 上游实际没有注册开始银趴、结束银趴，只存在 toggle 类型的锁牛牛别名。新实现按用户要求提供明确幂等群开关，默认开放，关闭阻止聊天中的查询和排行但不删除数据。
- 管理指令通过宿主权限等级 3 双重校验，不继续使用旧角色数组首元素和示例白名单。跨用户操作验证同平台群成员；已删除的个人锁入口不通过 UI 重新引入。
- `src/render.ts` 使用 Takumi 1.8.7 节点树、固定离线 Noto Sans SC 字体缓存与至多两个并行渲染。昵称只能成为文本，图片不下载头像。卸载取消渲染，渲染失败回退明确标记的文字排行。
- `client/` 以 ui-kit、locale、类型化 state/action 提供管理页。服务端 action 校验 Schema 与权限；仅返回有限范围排行，不包含冷却时间。普通页面沿用宿主滚动区域，不覆盖指针或模态。
- 源码只在独立项目维护，通过白名单脚本单向同步。测试运行在独立宿主配置和 SQLite 数据库，不修改真实用户数据。保留 MIT 上游声明。

## Alternatives considered

- 按群拆分长度：改变原有跨群玩法，因此只隔离群开关与参与关系。
- 保留原锁定 toggle：与开始/结束语义相反且不可安全重试，因此不用。
- Puppeteer 截图或远程字体：违反 Takumi 与移除字体配置要求，并增加浏览器/网络生命周期问题。
- 自动读取旧 Koishi 表：缺少平台映射及用户迁移授权，因此不自动转换。

## Consequences

新增独立表；旧数据不会自动迁移。帮助目标必须是当前群成员。挖矿失败会向正方向反弹。群榜是历史参与名单，退出群的历史记录仍可能出现。宿主权限插件决定平台角色映射，群开关命令不会自行提升权限。独立 WebUI 依赖宿主 ui-kit 的主题、原生细滚动条及浮层行为，优先于全局自绘滚动条约定。
